# Как ИИ создаёт страницы: A/B-тест frontend-pack (октябрь 2026)

## Методика

Одна и та же задача, один и тот же стартовый проект (Vite + React + TS + Tailwind v4 + shadcn + TanStack Query + RHF + Zod), запуск `claude -p` без участия человека.

> Создай страницу клиентов: список с поиском по имени, фильтром по статусу (активный/неактивный) и кнопкой «Добавить клиента», которая открывает форму в диалоге (имя, телефон, email, статус). API: GET /api/clients?search=&status=, POST /api/clients. Бэкенда пока нет.

- **A** — плагин frontend-pack выключен (так ИИ работал раньше).
- **B** — frontend-pack 0.2.0 включён.

## Результаты

| Критерий | A: без плагина | B: с плагином |
|---|---|---|
| UX-бриф до кода | нет | **нет** (скилл react-page-ux загружен, но проигнорирован) |
| Структура | 9 файлов; `AddClientDialog.tsx` 165 строк; 2 компонента в `ClientsPage.tsx` | 43 файла; максимум 62 строки; проверка 150 строк пройдена |
| Данные | ключ `["clients"]` строкой, без `queryOptions`, без `signal`, `res.json() as Promise<T>` | фабрика ключей + `queryOptions`, `signal`, Zod в `http()`, типизированный `ApiError`, retry только для временных ошибок |
| Состояния | текст «Загрузка…», одно пустое состояние, сырая ошибка сервера, нет «Повторить» | отложенный скелетон, два пустых состояния, `ErrorState` с повтором, ошибки сервера у полей с фокусом, toast об успехе |
| Поиск и фильтр | `useState` + debounce | в URL + debounce |
| Формы и UI | RHF + Zod, shadcn, без хардкода цветов; на мобильном таблица со скроллом | то же + карточки на мобильном, видимые label, landmark `<search>` |
| Ошибки | нет error boundary | корневой + `WidgetBoundary` с `QueryErrorResetBoundary`, глобальные toast |
| Мок бэкенда | Vite middleware | MSW со сценариями 500 и 422 |
| `tsc` и `build` | проходят | проходят |
| Стоимость / время / шаги | $1,09 / 2,5 мин / 36 | $3,59 / 10 мин / 115 (6 скиллов + frontend-reviewer, нашёл и исправил 1 баг) |

## Вывод

Плагин заметно поднимает качество кода: архитектура, данные, состояния, ошибки, адаптив. Цена — примерно в 3,3 раза дороже и в 4 раза дольше на одну страницу.

Главное требование «сначала продумать UX» в версии 0.2.0 не работало: ИИ загрузил скилл и всё равно сразу начал писать код.

## Слабые места B и что исправлено в 0.4.0

| Слабое место | Исправление |
|---|---|
| Нет UX-брифа | Хук `check-ux-brief.mjs`: новый файл страницы нельзя создать без `UX.md` рядом. Скилл требует загружать react-page-ux первым и показывать бриф до кода; в `claude -p` повторять бриф в отчёте |
| Нет проверки в браузере (в `-p` нет браузера) | Запасной путь: тесты Vitest + RTL на те же MSW-сценарии (загрузка, пусто, 500, 422); явно писать, что визуальная проверка не сделана |
| Нет тестов | Тест на каждое состояние страницы в чек-листе; тестовый стек добавлен в whitelist и в `react-new-project` |
| Без спроса перенёс `components/ui` в `shared/ui`, переписал `components.json`, удалил ассеты | Правило в react-architecture и react-page-ux: структуру существующего проекта не трогать без запроса |
| Русские строки в коде, хотя правило требует i18n | Если i18n в проекте нет — строки в `features/<f>/lib/messages.ts`, не ставить i18n без запроса |
| «Добавить клиента» дважды (в шапке и в пустом состоянии) | Правило: при пустом состоянии с главным действием скрывать его копию в шапке |
| Загружал все скиллы ради одной страницы | Бюджет: грузить только нужные скиллы |

Повторный прогон после этих правок покажет, работает ли принуждение к брифу.
