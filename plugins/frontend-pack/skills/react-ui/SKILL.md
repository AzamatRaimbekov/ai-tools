# React UI (shadcn/ui + Tailwind v4)

Scope: how components look and are composed. Loading/empty/feedback flows belong to `react-ux`; error handling to `react-error-handling`; data fetching to `react-data-fetching`; folder layout and naming to `react-architecture`.

> Precedence: if another installed skill or plugin (frontend-design, shadcn, web-design-guidelines, etc.) conflicts with `rules/libraries.json` or the Mdigital skills, the Mdigital rules win. External skills add taste, audits and tooling; they never change our libraries, folder layout, file limits or data layer.

## Where UI code lives

| Path | Holds | Rule |
|---|---|---|
| `src/shared/ui/` | shadcn primitives (`button.tsx`, `dialog.tsx`, ...) | Owned, edited in place, generated by the shadcn CLI |
| `src/shared/components/` | Reusable composites (`PageHeader`, `DataTable`, `Stack`) | Built only from `shared/ui` + tokens |
| `src/features/<f>/components/` | Feature UI | Composes shared pieces; never restyles a primitive locally |
| `src/shared/lib/utils.ts` | `cn()` | The only class-merging helper |
| `src/app/globals.css` (or `src/index.css`) | Tokens, `@theme inline`, dark overrides | The only place colors/radii/fonts are defined |

`components.json` aliases must point at this layout (`ui` -> `@/shared/ui`, `utils` -> `@/shared/lib/utils`, `hooks` -> `@/shared/hooks`). See `references/shadcn-setup.md`.

## 1. Reuse before you write

1. Check `src/shared/ui` for the primitive. 2. If missing, add it: `npx shadcn@latest add <name>`. 3. Only then write a custom component.

- Never copy a primitive into a feature folder to tweak it. Change it once in `shared/ui` (add a variant) or wrap it in `shared/components`.
- Never hand-roll dialogs, menus, popovers, comboboxes, tabs, tooltips. The headless primitive (Base UI or Radix) handles focus trap, keyboard and ARIA.
- Know your base: Radix projects compose with `asChild`, Base UI projects (shadcn default since July 2026) with `render`. Check `components.json` / existing `shared/ui` imports and match them.

## 2. Variants with cva, not boolean props

```tsx
// BAD: boolean props + conditional class soup
<button className={`px-4 ${isDanger ? "bg-red-600" : isGhost ? "bg-transparent" : "bg-blue-600"} ${small ? "text-xs" : ""}`} />

// GOOD: one cva per component, finite named variants
const badgeVariants = cva("inline-flex items-center rounded-md px-2 py-0.5 text-xs font-medium", {
  variants: {
    tone: {
      neutral: "bg-secondary text-secondary-foreground",
      success: "bg-success text-success-foreground",
      danger: "bg-destructive text-white",
    },
  },
  defaultVariants: { tone: "neutral" },
})

type BadgeProps = React.ComponentProps<"span"> & VariantProps<typeof badgeVariants>

export function Badge({ className, tone, ...props }: BadgeProps) {
  return <span data-slot="badge" className={cn(badgeVariants({ tone }), className)} {...props} />
}
```

- Name variants by meaning (`tone`, `size`, `density`), not by look (`red`, `big`).
- Use `compoundVariants` for combinations, never nested ternaries.
- Export `xxxVariants` alongside the component when other elements must look the same (e.g. a link styled as button).
- Details: `references/variants-cva.md`.

## 3. cn() everywhere

- Merge classes only with `cn()` from `@/shared/lib/utils`. Never string-concatenate or template-literal classes.
- Space children with `flex`/`grid` + `gap-*`, not `space-y-*`/`space-x-*` or margins on children.
- Toasts always go through `sonner` (`toast()`), also in Base UI projects; do not add the Base UI toast component.
- Every styled component accepts `className` and passes it last: `cn(base, variants, className)` so callers can override.
- Conditionals go inside `cn`: `cn("border", isActive && "border-primary")`.

## 4. Design tokens only

```tsx
// BAD
<div className="bg-[#1e40af] text-[#fff] p-[13px] rounded-[7px]" style={{ marginTop: 18 }} />
<p className="text-gray-500 dark:text-gray-400" />

// GOOD
<div className="bg-primary text-primary-foreground p-3 rounded-lg mt-4" />
<p className="text-muted-foreground" />
```

- Colors: semantic tokens only (`bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `border-border`, `bg-primary`, `bg-destructive`, `ring-ring`). No hex, rgb, oklch or raw palette (`blue-600`, `gray-500`) in components.
- Need a new color (warning, success, brand)? Add a token pair in globals.css (`--warning` + `--warning-foreground`, light and `.dark`) and map it in `@theme inline`. See `references/tokens-and-theming.md`.
- Spacing/sizing: the Tailwind scale (`p-4`, `gap-6`, `size-9`). Arbitrary values (`w-[372px]`) only for a real external constraint, with a comment explaining why.
- No `style={{...}}` except for truly dynamic runtime values (e.g. a computed width from a virtualizer, a CSS variable from data). Even then prefer `style={{ "--progress": `${pct}%` }}` + a class.
- Radius from `--radius` (`rounded-md/lg/xl`), shadows from the scale (`shadow-xs/sm/md`).

## 5. Typography and spacing scale

- Use the type scale (`text-xs` .. `text-3xl`) plus `font-medium/semibold`, `tracking-tight` for headings. Do not invent sizes.
- Pick a rhythm and stick to it: `gap-2` inside controls, `gap-4` inside cards, `gap-6`/`gap-8` between sections.
- Prefer `gap-*` on flex/grid parents over margins on children. No `mt-*` on a reusable component's root.
- Use `size-*` instead of `w-* h-*` pairs for squares/icons.
- Long text: `truncate` or `line-clamp-*`, and `min-w-0` on the flex child that truncates.

## 6. Responsive, mobile-first

```tsx
// BAD: desktop-first, sm: used to mean "mobile"
<div className="grid grid-cols-3 sm:grid-cols-1" />

// GOOD: unprefixed = mobile, prefixes add from that width up
<div className="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3" />
```

- Write the mobile layout first, then add `sm: md: lg: xl:`.
- Use container queries (`@container`, `@md:`) for components that live in variable-width slots (cards, sidebars).
- Touch targets at least 24x24 px (prefer `size-9`+ for icon buttons on touch UIs).
- Check 375px, 768px and 1280px before finishing. No horizontal scroll on the page.

## 7. Dark mode via tokens

- Dark mode is the `.dark` class on `<html>` overriding the same CSS variables. Components never need `dark:` for colors when they use tokens.
- `dark:` utilities are allowed only for non-color tweaks a token cannot express (e.g. `dark:shadow-none`) or inside `shared/ui` primitives as shadcn ships them.
- Theme switching: `next-themes` (Next.js) or the shadcn `ThemeProvider` (Vite) in `src/app/providers`. Support light / dark / system.

## 8. Semantic HTML first

```tsx
// BAD
<div onClick={save} className="btn">Save</div>
<div className="title">Orders</div>

// GOOD
<Button onClick={save}>Save</Button>
<h1 className="text-2xl font-semibold tracking-tight">Orders</h1>
```

- Clickable = `<button>` (action) or `<a>`/router `Link` (navigation). Never `div onClick`.
- Use landmarks (`header`, `nav`, `main`, `aside`, `footer`), one `h1` per page, ordered headings, `ul/ol` for lists, `table` for tabular data, `form`/`label`/`fieldset` for forms.
- Reach for ARIA only when no native element fits; a role is a promise of keyboard behavior.

## 9. Accessibility in every component

- Accessible name for every control. Icon-only buttons get `aria-label` (or `<span className="sr-only">`).
- Never remove focus outlines without replacement: keep `focus-visible:ring-[3px] focus-visible:ring-ring/50` from shadcn primitives.
- Contrast: text 4.5:1 (3:1 for large text), UI boundaries and icons 3:1. Do not lower opacity of text tokens to "soften" it; use `text-muted-foreground`.
- Every input has a visible `<Label htmlFor>`; errors are linked with `aria-describedby` and `aria-invalid` (shadcn `Field`/`Form` does this).
- Respect `motion-reduce:` for non-essential animation.
- Details and widget patterns: `references/accessibility-ui.md`.

## 10. Icons

- `lucide-react` only (the shadcn default). Import named icons: `import { Plus } from "lucide-react"`.
- Size with `size-4`/`size-5` (buttons already size child SVGs), color via `currentColor` (inherits text token).
- Decorative icons next to text: `aria-hidden="true"`. Icon-only: label the button, not the svg.
- Custom brand SVGs live in `src/shared/ui/icons/` as components using `currentColor`.

## 11. Composition over prop explosion

```tsx
// BAD: every new need adds a prop
<Card title="Revenue" subtitle="Last 30 days" icon={<Chart />} footerText="Updated now" showDivider actions={[...]} />

// GOOD: slots/compound components, children carry the content
<Card>
  <CardHeader>
    <CardTitle>Revenue</CardTitle>
    <CardDescription>Last 30 days</CardDescription>
    <CardAction><RangeSelect /></CardAction>
  </CardHeader>
  <CardContent><RevenueChart /></CardContent>
</Card>
```

- More than ~6 visual props or any `renderX`/`showX` flag pile = split into compound parts or accept `children`.
- Polymorphism via `asChild` (Radix) / `render` (Base UI), not an `as` prop with generic gymnastics: `<Button asChild><Link to="/new">New</Link></Button>`.
- Layout primitives (`Stack`, `Cluster`, `PageContainer`) in `shared/components` when the same flex/grid recipe repeats 3+ times. Do not build a layout component for a one-off.
- One component per file, file ≤150 lines; split parts into sibling files when exceeded.
- Patterns and examples: `references/composition-patterns.md`.

## 12. React 19 refs

```tsx
// BAD (legacy)
const Input = React.forwardRef<HTMLInputElement, Props>((props, ref) => <input ref={ref} {...props} />)

// GOOD: ref is a normal prop
function Input({ className, ...props }: React.ComponentProps<"input">) {
  return <input data-slot="input" className={cn("h-9 rounded-md border px-3", className)} {...props} />
}
```

- Type props with `React.ComponentProps<"tag">` (includes `ref`) and spread `...props` onto the DOM node so `asChild`/`render`, refs and ARIA pass through.
- Add `data-slot="name"` to the root of shared components for parent-level styling hooks.

## 13. Presentational components stay presentational

```tsx
// BAD: a shared/presentational card (shared/components) fetches data
function StatCardWithData({ id }: { id: string }) {
  const { data } = useQuery(orderQueries.detail(id))
  return <StatCard>{data?.title}</StatCard>
}

// GOOD: shared component renders props; a feature component takes the id and uses a query hook
function OrderSummary({ orderId }: { orderId: string }) {   // features/orders/components/OrderSummary.tsx
  const { data: order } = useQuery(orderQueries.detail(orderId))
  return order ? <OrderCard order={order} /> : <OrderCardSkeleton />
}
```

- `shared/ui` and `shared/components` never import from `features/*`, `api`, TanStack Query or stores.
- Feature components may take an id and use a query hook (`react-architecture` section 9); keep the query in the hook, not in JSX-heavy files.

## 14. Animation

- Default: Tailwind transitions + `tw-animate-css` (shadcn's `animate-in`, `fade-in`, `slide-in-from-*`).
- `motion` (`motion/react`) only for gestures, layout/shared-element or orchestrated sequences. Always honor reduced motion.

## Checklist before finishing

- [ ] Used existing `shared/ui` primitives; new primitives added via `npx shadcn add`, not hand-copied
- [ ] No primitive forked into a feature folder; changes made once in `shared/ui` or a wrapper in `shared/components`
- [ ] Variants via `cva` with semantic names; no boolean styling props or nested class ternaries
- [ ] All class merging via `cn()`; component accepts and forwards `className`
- [ ] No hex/rgb/raw palette colors, no unjustified arbitrary values, no static `style={{}}`
- [ ] Spacing and type from the scale; `gap` over margins; consistent rhythm
- [ ] Mobile-first; checked at 375 / 768 / 1280 px; no horizontal page scroll
- [ ] Looks correct in light and dark without per-component `dark:` color overrides
- [ ] Semantic elements; no `div onClick`; heading order correct
- [ ] Every control has an accessible name; focus ring visible; contrast meets 4.5:1 / 3:1
- [ ] Icons from `lucide-react`, decorative ones `aria-hidden`
- [ ] Composition (children/compound/asChild or render) instead of prop explosion
- [ ] No `forwardRef`; props typed with `React.ComponentProps<...>` and spread
- [ ] Presentational components have no data fetching or store access
- [ ] One component per file, ≤150 lines
